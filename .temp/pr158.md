## What
- Every tracked `.ts`/`.tsx` file (scripts, src, unit and e2e tests) is free of type errors in both modes of the workspace checker (`.claude/tools/etfs/tc/check.sh`)
- `import.meta.dir`/`dirname` -> `__dirname`, `import.meta.main` -> `require.main === module`, top-level `await` -> `main().catch(...)` (fetcher, backup script, e2e scripts and runner)
- Spreads and `for...of` over `Set`, `Map`, iterators and typed arrays -> `Array.from` / `forEach`
- `src` files reference their lib (`/// <reference lib="esnext" />`), tests reference `bun` and `node`
- All 44 `@ts-ignore` lines removed: React is imported as a namespace (a default import needs `esModuleInterop` in the IDE), `inert` takes a boolean (React 19 typings)
- Real type mismatches fixed after checking each one: `DeskColumnKey` derives from `SideColumnSettings` (lambda..color were missing, only used as React keys so no runtime bug); `DeskView.getDates` returns `Promise<unknown>` (the result is ignored); the unused `agEnabled` prop passed to `ChartView` is dropped (ChartView derives it from `metrics`); recharts types tick `x`/`y` as `number | string`, the colored tick now coerces them so the `dx` offset can never be a string concatenation; axis color helpers take named keys so `MetricColorSet` fits; `netGexPlusMinusMinDistance` takes the override table as an optional argument so the test no longer mutates a readonly export
- `.temp/` gitignored for local work files

## Why
The owner's IntelliJ runs TypeScript 5.9.3 on files without a tsconfig with its defaults (target ES5, module commonjs) and showed TS1343 at `scripts/options-data.ts:372` and `scripts/options-data.test.ts:61` and TS2802 at the `matchAll` spread of the ticker hint test. The checker only ran `--target esnext --module esnext`, so it never saw them. It now also runs that IDE mode (TS 5.9.3, no target/module flags) and reproduces exactly those errors on main.
